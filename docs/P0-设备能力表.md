# P0 设备能力表（实机采集）

> 采集时间：2026-11-05 16:55 – 17:45
> 采集工具：`hid_probe.cpp`、`mouse_probe.cpp`、`rawkbd.cpp`、`kb_probe.cpp`、`kb_info.cpp`、`kb_read.cpp`
> 协议来源：实机验证 + `new-hub.eweadn.cn`（E HUB 3.3.5）主包静态分析

## 1. 鼠标：Mchose A7 Pro（已验证）

### 1.1 设备标识

| 项目 | 实测值 |
|---|---|
| VID / PID | `0x5253` / **`0x1021`** |
| bcdDevice | `0x1419` |
| 厂商 / 产品 | RealTek / MCHOSE A7 Pro |
| 序列号 | 0123456789 |

### 1.2 接口拓扑（5 个）

| # | 路径片段 | UsagePage/Usage | IN | OUT | FEAT | ReportID（IN/OUT/FEAT） | 用途 |
|---|---|---|---|---|---|---|---|
| 1 | `mi_00` | `0x0001/0x0002` | 8 B | – | – | 0x01 / – / – | 鼠标 |
| 2 | `mi_01&col01` | `0x0001/0x0006` | 11 B | 2 B | – | 0x07 / 0x07 / – | 宏键 |
| 3 | `mi_01&col02` | `0x000C/0x0001` | 3 B | – | – | 0x0C / – / – | 消费者控制 |
| 4 | `mi_02&col01` | `0xFF0B/0x0104` | 61 B | 61 B | 61 B | 0x2A,2C,2D / 2A,2D / 2A,2B | 厂商副通道 |
| 5 | `mi_02&col02` | **`0xFF01/0x0001`** | 65 B | 65 B | 65 B | 0x11–14 / 13,14 / **11,12,14** | **配置主通道** |

### 1.3 报文长度

| ReportID | 实际长度（含 ID） | 用途 |
|---|---|---|
| `0x11` | **21 B**（1 + 20） | 短命令 |
| `0x12` | **65 B**（1 + 64） | 长命令 |

> `HidP_GetCaps` 只报最大值 65 B。发送 `0x11` 应使用 21 B 缓冲。

### 1.4 帧格式（`0x11 0x06` 读电量，已验证）

- 发送：`byte0 = ReportID`（不取反），`byte1..end = 命令与载荷 ^ 0xFF`
- 响应：`byte0 = ReportID`，`byte1 = 命令 ^ 0xFF`（回显匹配），`byte2.. = 载荷 ^ 0xFF`

实测响应 `11 F9 AC AD EF FF FA ...` → 回显校验通过，**电量 = 83%**（`payload[0]`），三次采样一致。

| 字段 | 值 | 状态 |
|---|---|---|
| `payload[0]` | 83 | ✅ 电量 |
| `payload[1]` | 82 | ❓ 文档称"充电状态"，语义待插拔线确认 |

## 2. 键盘：EWEADN X87（协议已解，电量可读）

### 2.1 归属判定

标准键盘 HID 集合被系统独占（`CreateFile` 返回错误码 5），改用 Raw Input（`RIDEV_INPUTSINK`）捕获：

**40 秒内 163 次按键，100% 来自 `VID_0C45&PID_FEFE&MI_00`**，其余端点零命中。

### 2.2 协议来源

静态分析 `new-hub.eweadn.cn` 主包 `main.59124dce33c280445fd9.js`（E HUB 3.3.5），其设备白名单中明确包含：

```js
{vendorId: 3141, productId: 65278, identifier: "3141:65278:2.4G Dongle:1:26"}
// 3141 = 0x0C45, 65278 = 0xFEFE
```

→ 该接收器是 E HUB 官方支持设备，协议可从驱动代码还原，无需抓包。

### 2.3 通道与帧格式（实测确认）

**主通道：`0xFF60/0x0061`，Output/Input 各 33 B（1 B ReportID + 32 B 帧）**

请求（32 B，前置 `ReportID = 0x00` 后写入）：

```
offset  0     1     2     3     4     5 .. 31
value  0xAA  0x10  0x18  0x00  0x00    0x00
含义   header cmd  len   addrL addrH   数据区
```

响应（33 B）：

```
offset  0     1     2     3      4..7    8        9 ..
value  0x00  0x55  cmd   len    0x00    包元数据  设备信息区
```

> **偏移说明**：E HUB 代码从 `slice(8)` 解析，但 WebHID 的 `inputreport.data` 不含 ReportID，
> 而 Windows 侧 `resp[0]` 就是 ReportID，因此**实际信息区起点为 `resp[9]`**（差 1 字节）。

### 2.4 设备信息字段（`cmd = 0x10`）

以 `resp[9]` 为 `info[0]`：

| 字段 | 偏移 | 实测值 | 说明 |
|---|---|---|---|
| VID | `info[4..5]` LE | `0x0C45` | 与接收器一致 |
| PID | `info[6..7]` LE | **`0x8006`** | 键盘本体 PID（接收器为 0xFEFE） |
| 版本 | `info[8..9]` BCD | `0x80,0x23` | 解析为数值版本 |
| workMode | `info[16]` | `2` | 2 = 2.4G |
| **batteryLevel** | `info[17]` | **84** | **百分比，直接可用** |
| chargeStatus | `info[18]` | `0` | 0 = 未充电 |
| 灯效/固件版本 | `info[29..31]` | – | 本阶段未用 |

**三次采样结果（间隔 250 ms）**：

```
第 1 次 | VID 0x0C45  PID 0x8006  workMode 2  电量 84%  充电状态 0
第 2 次 | VID 0x0C45  PID 0x8006  workMode 2  电量 84%  充电状态 0
第 3 次 | VID 0x0C45  PID 0x8006  workMode 2  电量 84%  充电状态 0
```

> **精度结论（D6）**：键盘上报的是**真实百分比**，不是 4 档，无需档位映射。

### 2.5 命令枚举（来自驱动代码，供 P3/P4 使用）

对象 `_n`（功能码，作为帧的 `cmd`）：

| 值 | 名称 | 值 | 名称 |
|---|---|---|---|
| 1 | ResetFactory | 9 | ModifyDefaultAxis |
| 2 | SaveParam | 10 | DoubleLightingQuery |
| 3 | ConfigSwitch | 11 | SpecialLightingQuery |
| 4 | SystemSetting | 12 | RtPrecisionQuery |
| 5 | ReportRateSetting | 13 | SleepTimeQuery |
| 6 | CalibrationSetting | 14 | MacroSpaceInfoQuery |
| 7 | AxisLibraryQuery | 16 | ShakeOptimizationSwitch |
| 8 | EffectAreaQuery | – | – |

对象 `Zn`（顶层命令）：含 `Global`、`CustomCommand`、`Handle=16`、`ThreeD=17` 等。

**已知具体调用**（混淆代码中直接可见）：

- 设备信息：`{cmd: 16, contentSize: 56}`
- 逐键 RGB：`encode(6, 0, 每键 4 字节[键id,R,G,B])`
- 侧灯颜色：`encode(8, 2, [R,G,B])`
- 系统设置：`[Global, SystemSetting(4), 读/写(1/2), 参数]`
- 配置切换：`[Global, ConfigSwitch(3), 读/写, ConfigN]`
- 恢复出厂：`encode(15, ...)`（另一套 64 B 接口）

### 2.6 另一套 64 B 协议（0xFF59，本阶段未验证）

驱动内定义（`ct` 常量）：

```js
totalPacketSize: 63, headerLength: 6, checksumIndex: 62,
commandIdIndex: 0, commandParamIndex: 1,
totalPacketLengthIndex: 3, currentPacketIndex: 4, lengthIndex: 5
// checksum = 255 - (sum(bytes) & 0xFF)
```

对应 `0xFF59/0x0061`（65 B）。该通道对 `0x87` 命令返回固定帧 `0F 01 01 11`，**判定为鼠标类协议或另一功能域**，暂不使用。

### 2.7 已否定项

| 候选 | 结论 |
|---|---|
| Evision 公版（`0xFF1C/0x92/ID 4`） | ❌ usage page、usage、report ID 全不符 |
| QMK / VIA raw HID | ❌ `0xFF60/0x61` 虽形似，但 `get_protocol_version(0x01)` 返回 `00 55` 而非 `01 00 0C` |
